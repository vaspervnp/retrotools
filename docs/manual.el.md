## Η ιδέα σε μια παράγραφο

Ένα σύγχρονο πρόγραμμα ζωγραφικής σε αφήνει να βάλεις οποιοδήποτε χρώμα οπουδήποτε. Ένας
8-bit υπολογιστής όχι. Το Spectrum επιτρέπει δύο χρώματα ανά κελί 8×8· ο C64 απαιτεί τα
hardware sprites να είναι ακριβώς 24×21 pixels· ο CPC στοιβάζει δύο, τέσσερα ή οκτώ
pixels σε κάθε byte ανάλογα με το mode, οπότε το πλάτος ενός sprite πρέπει να είναι
πολλαπλάσιο του 2, 4 ή 8.

Το RetroTools γνωρίζει αυτούς τους κανόνες και τους εφαρμόζει ενώ σχεδιάζεις. Το
αποτέλεσμα είναι ότι ένα sprite που τελειώνεις εδώ **μπορεί όντως να τρέξει στη μηχανή** —
δεν ανακαλύπτεις στο export ότι ήταν αδύνατο εξαρχής.

## Σύνδεση

Δεν υπάρχουν τοπικοί κωδικοί. Συνδέεσαι με **GitHub** ή **Google**.

Εμφανίζονται μόνο οι providers που έχουν ρυθμισμένα κλειδιά. Αν δεν έχει ρυθμιστεί
κανένας, δες τη [Ρύθμιση OAuth](oauth-setup.el.md).

Αν συνδεθείς με δεύτερο provider που έχει το ίδιο email με υπάρχοντα λογαριασμό, η σύνδεση
**ματαιώνεται** και σου ζητείται να συνδεθείς με τον αρχικό. Είναι σκόπιμο: η αυτόματη
ένωση λογαριασμών βάσει email είναι γνωστός δρόμος κατάληψης λογαριασμού. Δέσε τον δεύτερο
provider από τις ρυθμίσεις, όπου η ταυτότητά σου είναι ήδη αποδεδειγμένη.

## Δημιουργία project

Ένα project έχει μία πλατφόρμα και ένα mode. Όλα μέσα του — sprites, παλέτα, ομάδες,
spritemaps — ακολουθούν τους κανόνες αυτού του mode.

Στη σελίδα **Τα projects μου** δώσε όνομα, διάλεξε πλατφόρμα και mode από τη λίστα, και
πάτα **Δημιουργία**.

Το mode δεν αλλάζει μετά. Τα pixel δεδομένα θα παρέμεναν έγκυρα, οι περιορισμοί όχι — ένα
sprite 16×16 είναι εντάξει σε CPC Mode 0 και αδύνατο ως hardware sprite του C64. Φτιάξε
δεύτερο project, ή κάνε export σε JSON και προσάρμοσε.

## Επιλογή πλατφόρμας και mode

Η λίστα ομαδοποιεί τα modes ανά μηχανή. Τι να διαλέξεις:

### Amstrad CPC

| Mode | Ανάλυση | Χρώματα | Πλάτος sprite | Σημειώσεις |
|---|---|---|---|---|
| Mode 0 | 160×200 | 16 | πολλαπλάσιο του 2 | Η συνήθης επιλογή για παιχνίδια. Τα pixels είναι **διπλάσιου πλάτους από ό,τι ύψους** |
| Mode 1 | 320×200 | 4 | πολλαπλάσιο του 4 | Τετράγωνα pixels |
| Mode 2 | 640×200 | 2 | πολλαπλάσιο του 8 | Στενά pixels, κυρίως για κείμενο |
| Mode 3 | 160×200 | 4 | πολλαπλάσιο του 2 | Ατεκμηρίωτο· ίδια κωδικοποίηση με το Mode 0 με λιγότερα pens |

Ο CPC είναι ο μόνος από τους τρεις με **προγραμματιζόμενη παλέτα**: κάθε ένα από τα 16
pens μπορεί να δείχνει σε οποιοδήποτε από τα 27 χρώματα υλικού.

### Commodore 64

| Mode | Μέγεθος | Χρώματα | Σημειώσεις |
|---|---|---|---|
| Hardware sprite — hires | **ακριβώς 24×21** | 1 + διαφανές | Καρφωμένο από το VIC-II |
| Hardware sprite — multicolor | **ακριβώς 12×21** | 3 + διαφανές | Φαρδιά pixels· εμφανίζεται 24 pixels φαρδύ |
| Χαρακτήρας — hires | 8×8 | 2 | |
| Χαρακτήρας — multicolor | 4×8 | 4 | Φαρδιά pixels |
| Bitmap — hires | ελεύθερο, πλάτος %8 | 2 ανά κελί 8×8 | |
| Bitmap — multicolor | ελεύθερο, πλάτος %4 | 4 ανά κελί | Φαρδιά pixels |

Ο C64 είναι ο μόνος με **πραγματικά hardware sprites** — και ο μόνος όπου κάποια slots
της παλέτας είναι **κοινοί καταχωρητές**. Δες [Παλέτα](#παλέτα).

### ZX Spectrum

| Mode | Μέγεθος | Σημειώσεις |
|---|---|---|
| Software sprite με attributes | ελεύθερο, πλάτος %8 | Bitmap συν πλέγμα attributes 8×8 |
| Software sprite μονόχρωμο | ελεύθερο, πλάτος %8 | Μόνο bitmap· τα χρώματα τα δίνει το φόντο. Ο συνηθέστερος τύπος σε παιχνίδια του Spectrum |
| UDG — χαρακτήρας 8×8 | καρφωμένο 8×8 | Η βάση για tile-based παιχνίδια |

## Ο pixel editor

Άνοιξε ένα sprite με **Επεξεργασία**. Ο καμβάς δείχνει το sprite στο τρέχον ζουμ, **με το
πραγματικό σχήμα pixel του mode** — ένα CPC Mode 0 sprite σχεδιάζεται διπλάσιου πλάτους
από ό,τι ύψους, γιατί έτσι θα φαίνεται στη μηχανή.

### Εργαλεία

| Εργαλείο | Τι κάνει |
|---|---|
| ✏ Μολύβι | Σχεδιάζει με το επιλεγμένο χρώμα. Σύρε για συνεχή γραμμή |
| ◻ Σβήσιμο | Σχεδιάζει το slot 0 |
| 🪣 Γέμισμα | Γεμίζει τη συνεχόμενη περιοχή ίδιου χρώματος |
| ／ Γραμμή | Σύρε από αρχή σε τέλος· το preview ακολουθεί τον δείκτη |
| ▭ Ορθογώνιο | Περίγραμμα |
| ▬ Γεμάτο ορθογώνιο | |
| ⌖ Επιλογή χρώματος | Θέτει το τρέχον χρώμα από το pixel κάτω από τον δείκτη |

**Το δεξί κλικ πάντα σβήνει**, όποιο εργαλείο κι αν είναι επιλεγμένο.

### Ζουμ και πλέγματα

Ο ολισθητήρας ζουμ πάει από 2× έως 32×. Δύο πλέγματα:

- **Πλέγμα pixel** — εμφανίζεται από ζουμ 6× και πάνω· πιο κάτω είναι απλώς θόρυβος.
- **Πλέγμα κελιών** — κόκκινο, σημαδεύει τα όρια 8×8 όπου ισχύει το όριο attributes του
  Spectrum και τα ανά-κελί χρώματα του C64. Εμφανίζεται μόνο σε modes που έχουν κελιά.

### Αναίρεση / επανάληψη

Ανά **πινελιά**, όχι ανά pixel: ένα σύρσιμο του μολυβιού είναι ένα βήμα αναίρεσης. Το
ιστορικό κρατά 100 βήματα και μηδενίζεται όταν αλλάζεις καρέ.

### Αποθήκευση

Αυτόματη, περίπου 1,5 δευτερόλεπτο μετά την τελευταία πινελιά. Το σήμα πάνω δεξιά λέει
**Μη αποθηκευμένο** ή **Αποθηκευμένο**. Η αλλαγή καρέ ή η έξοδος από τη σελίδα αποθηκεύει
πρώτα.

Η σχεδίαση γίνεται εξ ολοκλήρου στον browser, οπότε δεν περιμένει ποτέ τον διακομιστή.
Στέλνεται μόνο η ολοκληρωμένη πινελιά.

## Παλέτα

Το αριστερό panel εμφανίζει τα slots του mode. Κάθε γραμμή δείχνει το χρώμα, το όνομα του
slot στη γλώσσα της μηχανής (`PAPER`, `INK`, `Multicolor 0`, `Pen 3`), και τον καταχωρητή
υλικού από όπου προέρχεται.

Κλικ στο χρώμα για να σχεδιάσεις με αυτό το slot. Με τη λίστα αλλάζεις σε ποιο χρώμα
υλικού δείχνει το slot.

### Η προειδοποίηση «κοινό»

Κάποια slots του C64 είναι σημειωμένα **κοινό**. Είναι καθολικοί καταχωρητές — `$D025` και
`$D026` για multicolor sprites, `$D021` για το φόντο. Αλλάζοντας ένα από αυτά, αλλάζει για
**κάθε sprite στην οθόνη**, όχι μόνο για αυτό.

Έτσι δουλεύει το υλικό, και το εργαλείο το δείχνει αντί να το κρύβει. Αν δύο sprites
χρειάζονται διαφορετικά χρώματα σε κοινό slot, δεν μπορούν να εμφανιστούν ταυτόχρονα.

### Διαφάνεια

Τα slots που είναι σημειωμένα ως διαφανή δεν έχουν δικό τους χρώμα· φαίνεται το φόντο.
Εμφανίζονται ως ουδέτερο σκούρο τετράγωνο στην παλέτα και ως καρό γύρω από τον καμβά.

### Palette profiles

Το ίδιο χρώμα υλικού φαίνεται ελαφρώς διαφορετικά σε διαφορετικούς emulators. Κάθε project
καταγράφει ποιο profile χρησιμοποιεί:

- **CPC**: `nominal` (0/128/255) ή `measured` (σκουρότερο μεσαίο επίπεδο, πιο κοντά στο
  πραγματικό υλικό)
- **ZX**: `d8` ή `d7` — οι δύο αναγνώσεις του non-bright επιπέδου που υπάρχουν στη
  βιβλιογραφία
- **C64**: `pepto`

Αυτό αφορά μόνο ό,τι βλέπεις. Τα αποθηκευμένα δεδομένα είναι πάντα δείκτες χρωμάτων
υλικού, οπότε η αλλαγή profile δεν αλλοιώνει ποτέ το sprite.

## Καρέ και animation

Κάθε sprite ξεκινά με ένα καρέ. Το **+ Νέο καρέ** προσθέτει άδειο· τα αριθμημένα κουμπιά
εναλλάσσουν. Ένα sprite πρέπει να κρατά τουλάχιστον ένα καρέ — για να το ξεφορτωθείς,
διάγραψε το sprite.

Τα καρέ εξάγονται το ένα μετά το άλλο, οπότε ένα animation είναι ένα συνεχόμενο μπλοκ
bytes στη μνήμη.

## Ομάδες

Οι ομάδες είναι για οργάνωση, τίποτα άλλο: «Παίκτης», «Εχθροί», «Πλακίδια». Δημιούργησέ
τες στο κάτω μέρος της σελίδας του project και ανάθεσε κάθε sprite με τη λίστα στην κάρτα
του.

**Η διαγραφή ομάδας δεν διαγράφει τα sprites της** — απλώς μένουν αταξινόμητα.

## Spritemaps

Ένα spritemap είναι πλέγμα κελιών, με κάθε κελί να δείχνει σε ένα sprite. Χρησιμοποίησέ το
για animation strips, tilesets ή character sets — οπουδήποτε η θέση σε πλέγμα έχει νόημα.

Δημιούργησέ το στη σελίδα του project με όνομα και διαστάσεις· ανοίγει ο composer:

1. Διάλεξε sprite από την αριστερή λίστα.
2. Κλικ σε κελί για να το τοποθετήσεις.
3. **Δεξί κλικ σε κελί για να το αδειάσεις.**
4. Πάτα **Αποθήκευση**.

Οι διακόπτες **Οριζόντια / Κατακόρυφη αναστροφή** ισχύουν για τα κελιά που θα τοποθετήσεις
στη συνέχεια, και αποθηκεύονται ανά κελί — το ίδιο sprite μπορεί να εμφανίζεται
καθρεφτισμένο σε πολλά σημεία χωρίς αντιγραφή.

Η σμίκρυνση του πλέγματος πετάει τα κελιά που μένουν έξω. Αν τα κρατούσαμε θα ήταν αόρατα
αλλά θα επέστρεφαν σε μελλοντική μεγέθυνση.

## Εισαγωγή από PNG

Στη σελίδα του project, στο **…ή εισαγωγή από PNG**.

Οι διαστάσεις της εικόνας πρέπει να είναι έγκυρες για το mode. Ένα PNG 16×16 είναι εντάξει
για CPC Mode 0 και απορρίπτεται για hardware sprite του C64, που απαιτεί ακριβώς 24×21.

### Ο διακόπτης παλέτας

- **Ανενεργός (προεπιλογή)** — το εργαλείο διαλέγει τα χρώματα υλικού που καλύπτουν
  καλύτερα την εικόνα και **ενημερώνει την παλέτα του project**. Κατάλληλο για το πρώτο
  sprite.
- **Ενεργός** — η εικόνα προσαρμόζεται στην παλέτα που έχεις ήδη. Χρησιμοποίησέ το όταν
  υπάρχουν άλλα sprites, ώστε να μην αλλάξουν τα χρώματά τους.

### Τι σου λέει

Η εισαγωγή δεν αποτυγχάνει ποτέ σιωπηλά. Περίμενε μηνύματα σαν:

```
Η εικόνα έχει 256 διαφορετικά χρώματα και μετατράπηκε σε 16.
3 κελιά 8×8 της εικόνας είχαν πάνω από 2 χρώματα (έως 4) — το υλικό επιτρέπει 2
ανά κελί, οπότε τα υπόλοιπα χάθηκαν (attribute clash).
```

Το τελευταίο είναι ο κεντρικός περιορισμός του Spectrum. Το μήνυμα σου λέει ποιες περιοχές
χρειάζονται δουλειά, πριν το μάθεις από emulator.

Τα πλήρως διαφανή pixels πάνε στο slot διαφάνειας του mode, όπου υπάρχει.

Τα interlaced PNG απορρίπτονται με μήνυμα που το λέει — αποθήκευσε χωρίς interlace.

## Εξαγωγή

Στον editor, στο **Εξαγωγή**. Προσφέρονται μόνο οι μορφές που ταιριάζουν στην πλατφόρμα.

| Μορφή | Περιεχόμενο |
|---|---|
| `.bin` | Ωμά packed bytes, ακριβώς όπως θα κάθονταν στη μνήμη |
| Z80 assembly | `defb` για **rasm** (sjasmplus και pasmo δέχονται το ίδιο) |
| 6502 assembly | `!byte` σε διάλεκτο **ACME** |
| `.prg` | Δυαδικό C64 με διεύθυνση φόρτωσης — **φορτώνει κατευθείαν στον VICE** |
| C header | `const unsigned char …[]` για z88dk / cc65 / SDCC |
| PNG | Εικόνα preview με σωστή αναλογία pixel |

Οι μορφές πηγαίου κώδικα φέρουν σχόλιο επικεφαλίδας με το μέγεθος, τα bytes ανά γραμμή,
και την παλέτα σε **τιμές υλικού**:

```
; player
; Amstrad CPC — Mode 0 — 160×200, 16 χρώματα
; 16x16 pixels · 8 bytes/γραμμή · 128 bytes/καρέ · 1 καρέ
; Παλέτα:
;   0: Pen 0 = Black (firmware 0, hardware &54)
```

Το `&54` είναι αυτό που γράφεις στον Gate Array. Μια τιμή RGB θα ήταν άχρηστη — δεν
υπάρχει πού να τη γράψεις.

Για τα hardware sprites του C64 η εξαγωγή αναφέρει επίσης ότι τα δεδομένα πρέπει να
ευθυγραμμιστούν σε όριο 64 bytes και ότι ο sprite pointer είναι `διεύθυνση / 64`. Είναι η
πιο συχνή αιτία του «γιατί βλέπω σκουπίδια» στον C64.

### Μάσκες

Όπου το sprite έχει μάσκα, ο διακόπτης **Συμπερίληψη μάσκας** την προσθέτει μετά τα
δεδομένα κάθε καρέ, στη μορφή που περιμένει μια ρουτίνα `AND mask : OR data` του Z80: το
bit της μάσκας είναι `1` εκεί που φαίνεται το φόντο.

## Αντίγραφο ασφαλείας και μεταφορά

Το **Εξαγωγή JSON** στη σελίδα projects κατεβάζει ολόκληρο το project — sprites, καρέ,
μάσκες, attributes, παλέτα, ομάδες, spritemaps — σε ένα `.retrotools.json`. Είναι
αναγνώσιμο κείμενο, οπότε ταιριάζει σε git δίπλα στον κώδικα του παιχνιδιού.

Ανέβασέ το στο **Εισαγωγή από αρχείο**. Η εισαγωγή δημιουργεί πάντα **νέο** project και δεν
αντικαθιστά ποτέ τίποτα· γίνεσαι εσύ ο ιδιοκτήτης, ό,τι κι αν λέει το αρχείο.

Αν το αρχείο έχει πρόβλημα, παίρνεις όλα τα σφάλματα μαζί, όχι ένα τη φορά:

```
Sprite 'player' (id 1): Το mode απαιτεί ακριβώς 24×21 pixels (δόθηκε 8×8).
Spritemap 'tileset': κελί δείχνει σε ανύπαρκτο sprite 99.
```

Όταν η επικύρωση αποτυγχάνει, δεν δημιουργείται τίποτα.

## Κοινοποίηση project

Τα projects είναι ιδιωτικά από προεπιλογή. Θέτοντας την ορατότητα σε **Public** το project
γίνεται αναγνώσιμο από οποιονδήποτε έχει τον σύνδεσμο, ακόμη και από μη συνδεδεμένους
επισκέπτες.

Το public σημαίνει **μόνο ανάγνωση**. Κανείς πλην του ιδιοκτήτη δεν μπορεί να αλλάξει ή να
διαγράψει project, ό,τι ορατότητα κι αν έχει. Οι απόπειρες επιστρέφουν «δεν βρέθηκε» και
όχι «απαγορεύεται», ώστε να μη διαρρέει ούτε η ύπαρξη των projects των άλλων.
